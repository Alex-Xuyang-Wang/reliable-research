**AI coding assistants can improve code quality on specific tasks, but the evidence does not establish a consistent overall improvement.** Controlled studies report better functional correctness and readability in some settings, conflicting security outcomes, and no clear downstream maintainability benefit. Recent observational evidence also raises concerns about growing complexity. [1–5]

The strongest findings differ by quality dimension:

- **Correctness and readability: positive, task-specific evidence.** GitHub’s randomized trial involved 202 experienced developers implementing web-server API endpoints. Developers assigned Copilot were reported to be 53.2% more likely to pass all ten unit tests—a relative increase, not a 53.2-percentage-point gain. Blind reviews also reported improvements in readability (3.62%), reliability (2.94%), and maintainability (2.47%). These results support a benefit for the tested task, but the vendor-conducted experiment measured one exercise and reviewer judgments, rather than production defects or actual maintenance costs. [[1]](https://github.blog/news-insights/research/does-github-copilot-improve-code-quality-heres-what-the-data-says/)

- **Security: conflicting evidence.** Perry and colleagues found that participants using a Codex-based assistant produced less secure solutions to security-related programming tasks and were more likely to believe their code was secure. Conversely, Sandoval and colleagues’ study of 58 student programmers implementing a linked-list application in C found a comparatively small security impact: the assisted group’s critical-bug rate was no more than 10% above the control group’s. The latter result does not demonstrate improved security; together, the studies show that outcomes depend on the task and interaction setting. Both evaluated early-generation assistants, limiting extrapolation to current tools. [[2]](https://arxiv.org/abs/2211.03622) [[3]](https://www.usenix.org/conference/usenixsecurity23/presentation/sandoval)

- **Maintainability: no demonstrated improvement in a direct experiment.** A preregistered, two-phase study involving 151 participants, 95% professional developers, tested whether other developers could more easily extend AI-assisted code. Its randomized second phase found no significant differences in subsequent completion time or code quality. Bayesian analysis suggested any benefits were small and highly uncertain. This is stronger evidence about actual maintenance work than immediate reviewer ratings, although it examined bounded Java tasks using tools available in late 2024. A null result is not proof of equivalence or long-term safety. [[4]](https://link.springer.com/article/10.1007/s10664-026-10889-1)

- **Repository-level quality: concerning observational evidence.** He and colleagues compared Cursor-adopting open-source projects with matched controls using a difference-in-differences design. They found a temporary increase in development velocity alongside persistent increases in static-analysis warnings and code complexity. These are quality proxies, not confirmed production failures; the nonrandomized design also leaves greater uncertainty about causation than a controlled trial. [[5]](https://www.cs.cmu.edu/~ckaestne/pdf/msr26.pdf)

The defensible interpretation is therefore **conditional improvement, not a general quality guarantee**. Evidence that an assistant helps code pass tests does not establish that it also improves security or future maintenance. Quality should be judged separately across those outcomes, rather than inferred from faster coding or greater output. [1–5]
