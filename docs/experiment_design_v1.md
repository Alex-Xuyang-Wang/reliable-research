# Reliable Research — Experiment Design v1

## 1. Project Goal

Reliable Research is a research agent customized for literature research in
AI-Assisted Software Engineering, with a focus on AI coding assistants.

The project studies whether claim-level evidence verification can improve the
factual reliability and citation alignment of research reports generated by an
LLM research agent.

## 2. Research Question

> Can claim-level evidence verification improve the factual reliability and
> citation alignment of research reports generated by an LLM research agent?

AI coding assistants are the evaluation domain rather than the object of the
agent modification itself.


### Condition B — Verification-Enhanced System

The same original report is passed through the verification pipeline.

```text

        |
        v

        |
        v

        |
        v

        |

        |
```

Using the same original report for both conditions isolates the effect of the

## 6. Atomic Claim Extraction

The Atomic Claim Extractor converts a research report into machine-readable
factual claims.

Each claim contains:

```text
claim_id
claim
citations
source_sentence
```

The extractor is evaluated for:

- factual claim coverage
- false positives
- atomic splitting quality
- citation association
- formatting robustness

Extractor changes should be driven by observed failures on real development
reports and accompanied by regression tests.

## 7. Citation Resolution

The Citation Resolver will map citations attached to claims to referenced
sources.

Planned output:

```text
claim_id
citation_id
source_title
source_url
resolution_status
```

Resolution status:

```text
RESOLVED
UNRESOLVED
```

The resolver should support citation formats observed in real reports:

```text
[1]
[1,2]
[1–3]
[[1]](URL)
```

## 8. Evidence Source Policy

The primary experiment verifies claims against the sources cited by the
original report.

The main experiment will not search for arbitrary new sources to rescue an
unsupported claim.

The primary question is:

> Does the report's cited source actually support the associated claim?

Dynamic source search may be considered as a future extension.

## 9. Evidence Retrieval

For each claim and cited source, the Evidence Retriever will identify the most
relevant passages.

Planned pipeline:

```text
Source Document
        |
        v
Chunking
        |
        v
Lexical Retrieval + Semantic Retrieval
        |
        v
Rank Fusion
        |
        v
Top-k Evidence Passages
```

Initial design:

```text
Top-k: 5
Chunk size: approximately 500–800 tokens
Overlap: approximately 100 tokens
```

Retrieval parameters may be tuned only using development questions.

## 10. Semantic Verification

The verifier assigns one of three labels:

```text
SUPPORTED
CONTRADICTED
INSUFFICIENT_EVIDENCE
```

### SUPPORTED

The retrieved evidence directly supports the factual content of the claim.

### CONTRADICTED

The retrieved evidence directly conflicts with the claim.

### INSUFFICIENT_EVIDENCE

The cited evidence does not establish or contradict the claim strongly enough
to justify the statement.

An unresolved source is tracked separately as a citation-resolution failure.

## 11. Revision Policy

```text
SUPPORTED
→ retain the claim

CONTRADICTED
→ remove or correct the claim only when verified evidence supports the
  corrected version

INSUFFICIENT_EVIDENCE
→ remove, hedge, or explicitly qualify the claim

UNRESOLVED SOURCE
→ do not present the associated claim as verified
```

The revision stage should not introduce arbitrary new factual claims that have
not themselves been verified.

## 12. Primary Evaluation Metrics

### Unsupported Claim Rate

The proportion of factual claims that are not adequately supported by their
associated evidence.

Lower is better.

### Citation Alignment Accuracy

The proportion of evaluated claim–citation pairs for which the cited evidence
supports the associated claim.

Higher is better.

### Supported Claim Retention

The proportion of correctly supported baseline claims retained after revision.

This prevents the system from appearing reliable simply by deleting most of
the report.

### Verification Coverage

The proportion of factual claims for which the system obtains usable evidence
and produces a verification judgment.

## 13. Component Metrics

Additional diagnostic metrics include:

```text
Atomic Claim Extraction:
- claim recall
- false-positive count
- split / merge error rate
- citation association accuracy

Citation Resolver:
- citation resolution success rate

Evidence Retriever:
- evidence recall@5

Semantic Verifier:
- accuracy
- macro-F1
- confusion matrix

System:
- runtime
- token usage
- number of sources
- number of claims
```

## 14. Phase 2 Human Pilot

Q001 and Q002 are used for the initial real-data pilot.

Approximately 20–30 extracted claims are manually reviewed.

The review checks:

```text
whether factual claims were missed
whether non-claims were incorrectly extracted
whether multiple facts were incorrectly merged
whether claims were incorrectly split
whether citation association was preserved
whether formatting artifacts remained
```

Observed failures should be documented before changing extractor heuristics.

The extractor improvement workflow is:

```text
Observed Failure
        |
        v
Regression Test
        |
        v
Implementation Fix
        |
        v
Run Existing + New Tests
        |
        v
Re-run Q001/Q002 Extraction
```

## 15. Human Annotation Protocol

Each reviewed claim records:

```text
report_id
claim_id
claim_text
citations
should_exist
split_correct
citation_correct
format_clean
error_type
notes
```

A subset of claims should be independently reviewed by both team members.

Disagreements should be reviewed before final statistics are produced.

The pilot must also include report-level review so that factual claims missed
entirely by the extractor can be counted.

## 16. Final Experiment Procedure

For each benchmark question:

```text
1. Generate baseline research report
2. Save baseline report and metadata
3. Extract atomic factual claims
4. Resolve citations
5. Fetch cited sources
6. Retrieve top-k evidence passages
7. Verify each claim
8. Revise unsupported or insufficient claims
9. Save verified report
10. Human-evaluate a defined sample
11. Compute evaluation metrics
12. Compare baseline and verification-enhanced outputs
```
